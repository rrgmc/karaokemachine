KaraokeMachine

A karaoke machine that behaves like a commercial home unit: pick a song by number, it plays, the words highlight in time. It runs full-screen on a television, and any phone on the network is a remote over an HTTP API. Search the catalog, queue a song, change the key, skip.

What it does

Songs

  • MIDI and KAR files with embedded karaoke lyrics, in all three conventions that exist in the wild. Legacy encodings are detected rather than assumed.
  • Video songs — H.264/AAC MP4.
  • MP3+G songs — an MP3 with a .cdg of the same stem, which is what most commercial karaoke discs hold. The CD+G graphics are drawn here, in Rust.
  • UltraStar songs — the .txt a singing game times its words in, beside the MP3 it names. The words are highlighted syllable by syllable.
  • A 0–10 suitability rating for every file, with a breakdown. It also names the melody channel where it finds one confidently, and gives a reason where it cannot.

Playing

  • Full-screen on a television, drawn by SDL3, or in a window on a desktop — F toggles and the choice is remembered. On Linux it draws straight to DRM/KMS from a bare TTY, with no desktop installed.
  • Or on a television in another room. Started with --stream the machine opens no window and serves what it would have shown, picture and sound together, as one continuous HLS stream. A set, a phone or a computer opens the machine's own /watch/ page. The playlist is the interface, so anything that plays one takes /stream/live.m3u8. VLC, Kodi and the television's own media pipeline all do, with no browser at all.
  • Words highlight in time, syllable by syllable, on the sequencer's own clock.
  • Transpose and tempo per song, and a guide melody that can be muted.
  • A lyric timing offset in milliseconds, adjustable mid-song, because a television adds picture lag and a mixer takes the sound out early. It moves the highlight only — never the audio, because the microphones are in that audio.
  • Photographed wallpapers behind the words, crossfading, each one checked for contrast in the band the lyrics actually sit in.

Remotes, and the API

  • The machine serves a remote at its own address. Any phone on the network, no app to install, and a QR code on the idle screen.
  • A standalone offline remote keeping its own copy of a machine's catalog, so browsing, searching and favorites work with the machine switched off.
  • An HTTP API with a WebSocket event stream covering search, queue, transport, settings, packages, wallpapers, demo mode, microphones and audio output.
  • Found on the network by mDNS. One admin password, which the machine gives itself — a six-digit PIN on the idle screen. Everything that reconfigures the machine needs the password; nothing a singer does needs it. The admin routes all live under /api/v1/admin/.

Getting a corpus into shape

  • km-package-builder, a local web server over a folder of source files. Browse, search the lyrics themselves, rate, fix the names, group duplicates, and pick songs into packages by hand.
  • km-pack builds and validates packages, and km-lyrics dumps one file's parsed timeline. km-wallpaper-pack builds a wallpaper set, keeping what lyrics stay readable over.
  • A printed song book. Four columns — artist, number, title and first line — modeled on the book a commercial machine ships in a ring binder. The machine serves one for its own catalog, so it is not only a curation artifact.

Pictures and instruments, found for it

km-admin finds photographs the lyrics stay readable over, measured in the band of the screen the words occupy. It also offers General MIDI banks from a table of sixty-three, and it sends either to the machine. It sends a file you already have too: a package, a bank, a photograph of your own.

It is the half the machine cannot do itself. A box under a television has no shell, may have no way onto the internet, and should not be holding your accounts.

Pictures come from Openverse by default, and its packs may be passed on. Pixabay and Pexels work with your own API key, and their terms, which do not allow redistribution, are shown next to the key field.

Numbers that cannot clash

A song's number is bank × 1000 + slot. The slot is what the package numbered the song, 1 to 999, and the bank is the block of a thousand it sits in. Two packages that both number a song 500 cannot collide: one is 3500, the other 611500.

A package's bank comes from its id, so its numbers are the same on every machine. Install the same volume here and at a friend's house, in any order, and it takes the same bank both times. A printed song list therefore travels with the file.

A package holds at most 999 songs. It is not a storage limit, because the machine holds a thousand packages and so very nearly a million songs. It is a nudge towards curating a volume rather than pointing a tool at a folder. The corpus this was built against is a large one, and what somebody left out is the whole difference between a catalog and a heap.

Deliberately not

  • No scoring of singers.
  • No bare audio files, because an MP3 with no .cdg beside it contains no lyrics. No CD+G disc images either, only the file pair.
  • No video wallpapers: a video song is not a video background.
  • No pitch shifting of audio.
  • No microphone processing in the app. Hardware mixes the microphones, and the app handles control and state only.
  • No shaped scripts: Thai, Arabic and Indic need a text shaper this build does not include, and there is no right-to-left support. CJK works, though. A Japanese or Chinese song uses a font from the system, and lyric decoding already handles the legacy encodings listed above.

These are deliberate decisions rather than missing features. To propose a change, start with the decisions.

Getting it

Every package below is on the release page, one file per platform, with the sixteen carols beside them as a separate download. Building from source is the other way in — BUILDING.md is how, and it is one command per platform once the prerequisites are in.

PlatformWhat you get
Windows A setup program holding all seven products behind component checkboxes. It installs per-user and raises no UAC prompt, and offers to put itself on your PATH and to open .kmbuild corpus files. Or a portable folder: unzip it and run it.
macOS An Apple installer package — the same seven products behind six component ticks. Applications go to /Applications and command-line tools to /usr/local, already on your PATH. It asks for your administrator password once, and fetches nothing.
Debian, Ubuntu A .deb. Its ffmpeg and font dependencies are named rather than bundled, so apt supplies them. It installs as an ordinary application, with a menu entry, an icon and karaokemachine as a command. It also carries the television-appliance service, switched off.
Any Linux A .tar.gz. Unpack it anywhere, run it, delete it — no root and no package manager. It carries its own ffmpeg, because a folder can name no dependency.
Android, Google TV An APK carrying both ABIs, so it installs on a phone and on a television.
iPhone, iPad An .ipa for the machine and one for the remote, both unsigned. iOS takes no signature from a stranger, so you sign it yourself with your own Apple ID. It is the machine itself — the same synthesizer, catalog, display and API — and songs arrive through the Files app.

Sixteen carols, free

There is one package you can just download — Silent Night, Joy to the World, The First Noel, Hark! The Herald Angels Sing, O Come All Ye Faithful, What Child Is This and ten more. Every one public domain, four or five verses each, seventy-six minutes of singing in a 28 KiB file.

It is a separate download, and no install carries it. A fresh install starts empty on purpose, because you supply your own songs.

It is the only pack of its kind. A karaoke MIDI is not one work but four or five: the tune, the arrangement, the words, any translation, and whoever typed the notes in. Almost nothing in the world has all of those free and written down. Carols do.
