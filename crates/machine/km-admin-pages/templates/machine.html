{# **The errands, one at a time**, and the pattern is `km-package-builder`'s `.curate` strip by way of `km-admin`'s copy of it: flat radio siblings and `:checked ~`, no JavaScript. Two things about it are load-bearing rather than stylistic. **The radios are flat siblings of the panes.** A strip that wrapped each pane would need `:has()` to reach sideways out of itself, and `.pane { display: none }` is unconditional -- so a browser that could not evaluate that would show *no* pane and this tab's whole settings half would be gone. `:checked ~` has worked for a decade, and a stylesheet that fails to load leaves every section on the page, which is exactly the arrangement this replaces. **They sit outside every form.** There are five `POST` forms below, and a radio inside one of them would post a `machine-tab` key nobody reads. A test asserts this by position. **The order is `km-admin`'s**, because `Two admin surfaces, one vocabulary` requires that a page existing on both be named the same, in the same case, in the same place. Language is the one pane with no counterpart there -- that tool has no say over what the television speaks -- so it goes last rather than displacing anything. Debugging opens, because it is the one pane that is never empty. **A save comes back to the pane it was made on.** A notice about a rename, read underneath a debug switch, is a notice about a page somebody is no longer looking at. The pane rides in the redirect's query string, is checked against a fixed list of names by `handlers::back_pane`, and an unknown one opens Debugging -- so nothing a caller sends reaches the `checked` attribute or the redirect. `Pane::drawn` is the other half: a pane whose radio this host does not render would leave no pane open at all, `display: none` being unconditional. #}
